# Windows release verification

Version 0.1.6 shares a cancellable local-generation queue with CLI 0.7.9 across processes using the same OS user/home. Ollama/MLX generation and local runtime changes take turns; OpenRouter generation remains parallel. Slots are released before tools and approval, avoiding parent/worker deadlocks. The title bar shows waiting tasks in both themes. File tools and undo coordinate; unread overwrites and stale edits fail without changing newer contents. All patch targets are checked before the first operation. Opaque shell/plugin operations are serialized and checked against observed files, but undeclared writes and external editors require separate worktrees or user coordination; this is not OS isolation.

Verification on 2026-10-16 passed 531 CLI tests, 106 desktop tests, both strict typechecks, 17 fresh CLI package checks, and separate-process CLI checks for queue cancellation, forced owner exit, parallel OpenRouter fixtures, isolated histories and conflicting file changes. Two CLI processes completed independent real 4B local file-read tasks at 16K context and reported queue status; the model was unloaded. The packaged Windows application and a separate installed CLI shared the same queue, cancelled a waiting IDE task before inference and displayed/cleared the waiting indicator at 1000 × 700 in both themes. Its embedded CLI entry matched the tested package. All fourteen shutdown checks and nine forced-termination/undo recovery cases passed again, with plugin integrity, SQLite integrity, manual-edit protection and the native Undo control verified. Apple hardware and paid cloud inference remain outside this verification; OpenRouter tests use local protocol fixtures.

This checklist records the scope and evidence for the Windows x64 v0.1 release. Unsupported platforms and unverified cloud scenarios remain explicit limitations; they are not counted as passing. Release artifacts are published only after installed-build checks.

Version 0.1.5 makes Hugging Face downloads explicit: each result has a download arrow; choosing it shows confirmation in place of the list so the action remains visible in smaller windows. Models that exceed current memory explain why installation is unavailable. Download progress, cancellation, validation failures, retries and a shortcut to Installed are visible above the results. A real public Qwen3 0.6B GGUF download passed loading, a tool call and tool-result handling; the install-only flow released its memory. All 104 source tests and strict typecheck pass. The guided installer follows the [Hub's Ollama integration](https://huggingface.co/docs/hub/en/ollama), while MLX downloads model weights and tokenizer/configuration files with the [Hub snapshot downloader](https://huggingface.co/docs/huggingface_hub/en/guides/download).

Additional verification on 2026-10-16 used the released 0.1.5 application with a separate Ollama process and an empty model cache. A real download exposed progress; closing and reopening the picker retained the running job. Cancellation stopped the CLI child and retained partial files. Stopping the isolated runtime produced a visible error; restarting it allowed a successful retry, model selection and first chat response. The saved chat survived an app restart. The probe and final chat model were unloaded, and the isolated runtime was stopped. Fresh runs also passed all 510 CLI source tests and 17 isolated package checks; the fresh CLI tarball matched the published 0.7.7 SHA-256. The complete public Windows installer download matched its published SHA-256 and filename. These checks use real local inference; OpenRouter remains covered by documentation-based protocol fixtures rather than paid calls.

The same released application also passed 24 picker cases across four window sizes and both themes, download-control fixtures in two medium-window themes, nine forced-termination/file-undo recovery scenarios, and all 14 startup/discovery shutdown cases. Recovery preserved saved transcripts and checkpoints, kept SQLite integrity and foreign-key checks clean, protected manual file edits, and completed an interrupted two-file undo after restart. Windows shutdown/logoff messages were sent only to isolated QA windows; the computer was never shut down. A separate active-download quit check verified that a real CLI downloader terminated and its pending runtime request disconnected when the IDE quit. No additional product fix was required by these checks.

Version 0.1.4 uses OpenRouter's maintained AI SDK 7 adapter. A review of the current [integration](https://openrouter.ai/docs/guides/community/vercel-ai-sdk), [streaming](https://openrouter.ai/docs/api-reference/streaming) and [reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) documentation found that the generic OpenAI adapter discarded reasoning details and errors inside successful HTTP streams. Local protocol fixtures now verify encrypted reasoning through the desktop tool loop and JSON-restored transcripts, keep-alive comments, and errors before or after partial text. All 103 source tests and strict typecheck pass. This verifies the documented API contract without paid inference.

The model picker also stays below the window title bar and marks its surface as non-draggable. At 1000 × 700, the previous build placed tabs partly over Electron's draggable title bar, which suppresses pointer events. `verify:model-picker` covers 24 tab selections at four window sizes in both themes, plus keyboard navigation. The Windows installer offers to launch notch when interactive setup finishes; silent installation stays quiet.

Version 0.1.3 includes OpenRouter's `~provider/model-latest` aliases in both fresh and cached model catalogs. Invalid identifiers remain rejected, and browsing without a key does not enable inference. Local models require a verified native context limit as well as tool support; unknown, ambiguous and unsupported limits leave the model unavailable with an explanation. Models with known limits still use conservative memory estimates when detailed KV metadata is absent. The source suite has 100 passing tests and a clean strict typecheck. A live public catalog check found all 460 eligible text models, including 19 latest aliases, on October 15, 2026; the provider's catalog can change.

Version 0.1.1 fixes the startup shutdown races reported in 0.1.0. `verify:shutdown` covers fourteen early-quit/setup/window-close/discovery/plugin cases, checks main-process diagnostics and shutdown summaries, verifies that owned processes exit and checks SQLite integrity. Delayed app, plugin-view and model-list replies exercise cancellation inside the IPC tracker without extending IPC deadlines. Catalog verification can be interrupted during confirmed exit; no partially scanned catalog is marked verified. Unsaved-change confirmation remains active, and a vetoed quit leaves discovery available. These checks cover normal Windows application exit; forced process termination, OS shutdown and other platforms remain separate scenarios.

Version 0.1.2 adds nine recovery cases using the installed Windows application: forced exit after saved turns, interruption before atomic chat/checkpoint replacement, canceled session ending, shutdown/restart, logoff, critical close, startup termination and partial file-undo interruption. Restarts verify exact committed transcript/checkpoint contents, native turn identities, SQLite integrity and foreign keys, and the real Undo confirmation. A real Windows terminal also verifies published CLI 0.7.5 resume and undo after two forced terminations. These use isolated profiles and deterministic inference fixtures. Windows messages target only the test window; full computer shutdown and physical power loss remain untested.

The 0.1.2 context regression recovers measured SDK counts after runtime retirement without accepting another model’s usage. The native MCP regression demonstrates the old four-second deadline collision and verifies the six-second participant budget permits the existing three-second grace plus two seconds for Windows tree termination and exit confirmation; genuine force failure still fails. Overall shutdown deadlines are unchanged. The source suite has 98 passing tests and a clean strict typecheck.

Local model discovery keeps the last verified inventory for an unreachable server and displays a connection warning. A successful empty response removes old entries. Fresh results take priority over a cached duplicate, and local turns cannot use an unverified cached entry. Catalog maps change together so a pending refresh does not change another turn’s endpoint or context; cloud turns remain independent of local discovery. Regression tests cover transport failures, malformed responses, retry recovery, removal, duplicate endpoints and a cloud turn during refresh.

When a plugin host is still starting, shutdown waits for its process to exist and terminates it without requesting a response from an unready host. Running hosts retain their graceful shutdown period. This avoids spending that period on a startup process while respecting [Electron 43.7.9’s termination check](https://github.com/electron/electron/blob/v43.7.9/shell/browser/api/electron_api_utility_process.cc#L378), which rejects a process without a PID.

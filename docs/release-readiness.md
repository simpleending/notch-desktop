# Windows release verification

This checklist records the scope and evidence for the Windows x64 v0.1 release. Unsupported platforms and unverified cloud scenarios remain explicit limitations; they are not counted as passing. Release artifacts are published only after installed-build checks.

| Requirement | Current evidence / remaining work |
| --- | --- |
| First launch, branding, quiet setup, dark/light UI, keyboard navigation | Windows setup and workbench checks pass on the installed app. All 21 visible settings sections pass the branding check; all 552 renderer files are scanned, secondary illustrations replaced and renderer exports checked. Rare interactive states still need wider manual coverage. |
| Real local inference through the IDE | `verify:agent` runs the installed Hugging Face Qwen3.5 4B model through the real composer, native approval UI and CLI tools. Independent tests validate the resulting file. |
| Exact write and command approvals | Native write approval holds the file unchanged until approved; shell execution receives its own approval. Read-only selection, automatic-mode semantics and full-access UI coverage remain. |
| Accurate execution status and context usage | Packaged `verify:agent` proves known idle state, nonzero provider counts, correct context limit and persistence. Unit tests cover running/requires-action transitions and latest-request counts without summing earlier requests. |
| Context budgets and compaction | Real Qwen3.5 4B test at 8K compacts 18K estimated history to about 1K and recalls the original decision. Instructions/tool schemas, reply space, safety reserve and measured usage are included; original/current user boundaries and tool chains are preserved, with raw transcript archives. Native compaction progress returns to known idle after a successful continued request. Large multimodal inputs and extended cloud sessions need further validation. |
| Resume, cancellation, queueing and recovery | Completed native history and shared harness state survive restart, and a real follow-up resumes the same session without replaying the completed write. Native cancellation while a write approval is pending clears the approval and leaves the file absent. Cancellation during generation, queueing, transport failure and crash recovery need end-to-end coverage. |
| File review and undo without data loss | CLI checkpoints are persisted before writes and after tool completion. Workbench callbacks create native review entries with matching turn IDs. `verify:undo` uses the real composer/tools, restarts the app, previews an earlier turn without writing, blocks a manual conflict and restores that turn plus later changes. Unit tests cover create/delete, malformed histories, linked paths, workspace identity and retrying a partially interrupted restore. The CLI has an actual terminal restart/resume/undo check. Shell/external changes are not covered; unverified crash windows fail closed. Legacy preview checkpoints were not saved. |
| Local model discovery, downloading, loading and unloading | Installed/Hugging Face tabs, cached metadata, memory estimates, context settings and real Ollama inference pass Windows checks. Auto context uses fresh RAM/VRAM telemetry before each local turn, prefers GPU-resident contexts up to 128K and keeps 256K manual; modeled memory pressure preserves overrides without exceeding estimated fit. Install progress/cancellation and isolated install configuration have unit coverage; actual UI downloads, cold startup and physical memory-pressure behavior need broader verification. |
| Apple Silicon MLX | Supported Apple hardware gets an MLX choice; verified installs persist into the Installed list and route through the CLI runner. Real Apple hardware and native packaging validation remain. |
| Optional OpenRouter, OpenAI and Anthropic API keys | OpenRouter key UI, OS-encrypted storage, live catalog cache and harness routing are implemented. A protocol fixture verifies keys, output budget and real SDK parsing; live paid OpenRouter requests remain unverified. Direct OpenAI/Anthropic desktop controls remain. |
| Editor, files, terminal, Git, search and agent changes | Installed Windows checks pass for file opening, fff filename search and agent grep/glob. A deterministic provider fixture exercises real composer tools, pagination, ignore rules, edits and cancellation; compatibility queries work with an empty PATH using bundled ripgrep. The selected-turn undo workflow is verified separately. Terminal, Git, large-file and cross-platform workflows need broader verification. |
| Skills, MCP, extensions and advertised agent capabilities | All nine bundled plugins and 234 files have final branded SHA-256 entries; the runtime reports nine verified plugins and running native views. Packaging verifies the full inventory. Tamper tests reject changed/unlisted files. A local metadata validator replaces the unavailable worker during plugin discovery, without executing plugin commands. Validator caches are versioned. Arbitrary third-party plugin execution and unavailable agent SDK methods are not part of the Windows release claim. |
| Security and private data | Renderer isolation and workspace authorization are retained. IPC/navigation, credentials, untrusted content, permissions and sandbox/fuse audits remain. |
| Dependencies and bundled notices | Full npm audit is clean after upgrading esbuild to 0.28.2; core build, strict typecheck and policy/adapter tests pass. Packaging verifies the pinned native search executable and required bundled search notices; a full transitive notice audit remains. |
| Performance and resource cleanup | File search runs separately and releases idle indexes. Local inference is unloaded after QA. Startup, editing under inference, large repositories and memory need measured comparison with the original baseline. |
| Reproducible distribution and updates | The Windows installer has a pinned NSIS packaging script, its own executable metadata, bundled notices and SHA-256 checksums. Startup launches directly without a previous update launcher. Packaging still relies on the pinned installed base archive; signing, automatic updates and other OS builds remain. |
| Public source and final landing-page capture | Development source is public. The landing page uses two actual installed-app light-mode captures, showing the editor and model picker. Windows artifacts are published after their installed-build checks. This release verifies the listed Windows workflows; it does not claim every platform or integration is verified. |

Verification reports contain machine-specific paths and remain outside the public repository. Commands and fixture checks belong in the repository so results can be reproduced. The release notes must distinguish verified Windows workflows from remaining platform, signing, performance-parity and paid-inference work.

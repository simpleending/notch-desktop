## Distribution audit findings

What this repo does: Notch is a Windows desktop coding workbench with local model runtimes, optional cloud providers, persistent chats and model downloads. This audit assumes one desktop user with overlapping windows, downloads, model changes and background tasks; it does not assume a public multi-tenant server.

The audit traced the application/bootstrap and IPC boundaries, model discovery and selection, inference leases, install jobs, cancellation, context writes, session persistence, provider subprocesses, plugin validation, updater and installer packaging. The highest-risk paths received focused race and failure tests.

1. **Colibri cleanup could stop a newer mount.** Setup and validation previously ended before a separate unload call. A queued mount could run between those steps and then be stopped by the old install's cleanup. Setup, validation, unload and rollback now share the inference lease; the regression holds setup open and verifies mount ordering and cancellation. Without the fix, a model could disappear just after loading.

2. **Context validation could race a mount.** A model could start while its new memory/context plan was still being checked. Validation and persistence now hold the inference lease, serialize writes and update memory only after the disk write succeeds. The regression queues a mount behind a context change and checks the committed value. Without the fix, the displayed context and running model could disagree.

3. **A delayed Strata folder picker could change an active download's destination.** The busy check previously happened before awaiting the picker. The result now rechecks download activity under the inference lease, and directory persistence shares that lease. The regression starts a download while the picker is open. Without the fix, directory preferences could change during setup.

4. **Late Strata cancellation could commit a new selection.** Cancellation during the selected-model write previously returned success from the provider and left the new selection behind. Cancellation now restores the previous selection while still holding the lease. Both a prior model and an initially empty selection are tested. Without the fix, a cancelled job could replace the user's selected model.

5. **Installers could retain stale runtime dependencies.** Packaging refreshed source files but inherited much of its dependency tree from an older prototype. It now refreshes runtime dependencies from the tested installation and checks versions; inherited Zod copies are handled explicitly. Without this fix, dependency updates in the repository would not reliably reach downloads.

6. **Constrained Zod collections could exhaust memory.** Oversized arrays and sets were walked before their declared upper bounds were enforced. The compatibility backport and official v4 update reject them first, with ESM/CommonJS and packaged-copy checks. Without the fix, oversized invalid input could allocate an error for every element.

7. **Shared menu styles obscured the diamond shape.** The first rendered check found a rectangular background behind the new artwork. The diamond is now exempt from the generic menu surface rule. Its original glyphs, stable action positions, focus behavior and viewport placement are covered by unit and renderer checks; the corrected final screenshots were inspected in light and dark themes.

Verdict: the source fixes address the reproduced findings, and the final candidate passes the source, installer-integrity, dependency, rendered-UI and Strata lifecycle checks above. Installed-app and public-download verification are recorded separately before publication. Not checked exhaustively: every inherited/minified upstream implementation, every third-party dependency, macOS/Linux, paid providers, full-weight Strata inference and GPU benchmarks. These limits are not counted as passing tests.

Version 0.1.1 fixes the startup shutdown races reported in 0.1.0. `verify:shutdown` covers fourteen early-quit/setup/window-close/discovery/plugin cases, checks main-process diagnostics and shutdown summaries, verifies that owned processes exit and checks SQLite integrity. Delayed app, plugin-view and model-list replies exercise cancellation inside the IPC tracker without extending IPC deadlines. Catalog verification can be interrupted during confirmed exit; no partially scanned catalog is marked verified. Unsaved-change confirmation remains active, and a vetoed quit leaves discovery available. These checks cover normal Windows application exit; forced process termination, OS shutdown and other platforms remain separate scenarios.

Version 0.1.2 adds nine recovery cases using the installed Windows application: forced exit after saved turns, interruption before atomic chat/checkpoint replacement, canceled session ending, shutdown/restart, logoff, critical close, startup termination and partial file-undo interruption. Restarts verify exact committed transcript/checkpoint contents, native turn identities, SQLite integrity and foreign keys, and the real Undo confirmation. A real Windows terminal also verifies published CLI 0.7.5 resume and undo after two forced terminations. These use isolated profiles and deterministic inference fixtures. Windows messages target only the test window; full computer shutdown and physical power loss remain untested.

The 0.1.2 context regression recovers measured SDK counts after runtime retirement without accepting another model’s usage. The native MCP regression demonstrates the old four-second deadline collision and verifies the six-second participant budget permits the existing three-second grace plus two seconds for Windows tree termination and exit confirmation; genuine force failure still fails. Overall shutdown deadlines are unchanged. The source suite has 98 passing tests and a clean strict typecheck.

Local model discovery keeps the last verified inventory for an unreachable server and displays a connection warning. A successful empty response removes old entries. Fresh results take priority over a cached duplicate, and local turns cannot use an unverified cached entry. Catalog maps change together so a pending refresh does not change another turn’s endpoint or context; cloud turns remain independent of local discovery. Regression tests cover transport failures, malformed responses, retry recovery, removal, duplicate endpoints and a cloud turn during refresh.

When a plugin host is still starting, shutdown waits for its process to exist and terminates it without requesting a response from an unready host. Running hosts retain their graceful shutdown period. This avoids spending that period on a startup process while respecting [Electron 43.7.9’s termination check](https://github.com/electron/electron/blob/v43.7.9/shell/browser/api/electron_api_utility_process.cc#L378), which rejects a process without a PID.
